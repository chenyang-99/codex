# X 平台出稿适配器 v1.0.0｜上线审查记录

审查日：2026-10-20
发布位置：同仓库 .agents/skills/x-content-adapter/
入口：.agents/skills/ai-copy-production/SKILL.md v2.6.1 路由到本模块
**上线的含义**：在 GitHub 默认分支可被出稿流程读取，允许进入人工审稿/手动发布的日常生产；不代表经过 X 官方认证，也不等于在真实账号获得了增长结果。

## 研究与证据范围
- 查阅 X 官方 Original Content Rewards、X Premium、Articles、真实性和自动化政策。申请门槛和奖励合格曝光口径分开记录；没有公开的 50% 预览卡片计算公式。
- 案例库收录本人账号的高收藏工具帖与低曝光图文对照、@OpenDesignHQ 的实用演示、Christopher Fryant 的实验串推和 Prompt、Matt Shumer 的长篇观点、@jxnlco 短技巧；另用 21,864 条成功样本的选择偏差和 96 创作者形式对照，避免盲目断言哪个排版必胜。
- 数据源为 X 官方页面、项目已确认台账、研究者记录、媒体报道、作者自报。不是统一口径的 Creator Studio 合格曝光，不用于收益预测。

## 4 轮上线复核
R1｜政策审查：通过
- 已区分 Premium Basic 观看与创作者自己的收益申请档位；认证粉丝 500、近 90 天 50 万认证用户首页曝光、回复排除、合格曝光唯一/50%可见。
- 已标出不合格自动化创建/发布、低贡献聚合、版权和虚假亲测；没有把一般 X 自动化允许的行为直接套到奖励资格。
- 不把卡片排版/图片尺寸/爆款案例当计数公式。

R2｜编辑与格式设计审查：通过（规则与案例研究，不是实际用户满意度测试）
- 核短文字、图文、Thread、长帖、Article 这五种形态；结构选择基于信息体量、独立原创贡献和现有材料，不强制 Thread 条数、贴图数量、表情和 CTA。
- 保留原出稿 Skill 的观点/事实/作者声音/改稿范围锁。此前已公布的“AI漫画资源清单”不是因清单形式被判无原创；纯粘贴 README 的清单须退回研究。
- 找到并补上“稳定更新”的实际缺口：人工候稿队列、已发布去重、每轮只推进高价值的一稿、反馈复盘。

R3｜20 场景审稿规范审查：通过（静态人工对照，尚非 20 次独立语言模型生成实验）
- T01–T06 五种形式；T07–T09 用户局部修改、仅审稿、未亲测；T10–T12 版权/自动发布/伪曝光保证硬边界；
- T13–T16 曝光指标分离与作品状态；T17–T18 AI 审稿与本人发布；T19–T20 去重和小红书模块隔离。
- 预期行为及人工判断详见 references/regression-cases.md；这是一份可执行的测试契约，真实生成质量须随着后续稿件继续回归。

R4｜GitHub 静态接入与回读：通过
- 核验了 6 个规则与案例文件的默认分支内容、出稿核心中的调用引用、五种类型字段、官方链接、审稿状态机、收益资格硬边界、20 个回归用例。
- 第一次结构检查为 20/21：入口 Skill 中缺少明确的“用户人工实质性审改并自己发布”字面强约束（其他政策页已有）。已在入口文件修补，复检 21/21。
- GitHub 文件读回成功；没有依赖尚未部署的机器人、定时发布程序、私有第三方 API 或所谓有效曝光预测器。

## 上线结论
**准予 v1.0.0 作为人工参与的 X 内容出稿适配器使用**。它是可工作的编辑规程和平台路由，不是自动化发布产品、原创认证服务或已验证的增长算法。
后续每 7–14 天分析用户真实发布样本；若无数据，不推断曝光提高。官方规则一旦变化，优先核对并更新 policy 文档。新增小红书模块须独立审核，不继承 X 奖励计数规则。

- 未对该用户账号运行真实 A/B，也没有 X 按帖合格曝光权限；7.7K 是用户当轮自报，不是本系统取得的数据。
- 未由用户针对本版本生成的具体稿件进行审稿评分、上线效果或读者调研。
