# X 形式自动路由与阅读布局｜v1.2

## 前置问题卡
目标受众是谁？要解决什么真实问题？一条可验证的内容承诺是什么？作者实质性独立贡献是什么？有无真实图片、案例或材料？用户要求的 edit_scope 和形式是什么？
禁止先固定 12 条、6 图或长文章，再补没有信息增量的内容。

## 形式路由（不保证任何曝光效果）
1. short_text 纯文字单帖：一个判断、一个有价值的发现、一项短技巧、一个新闻事实及其影响；没有必须附图的独立证据。优先自然短句、适度分行、明确第一屏。
2. image_post 图文单帖：真实界面步骤、前后成果对照、可核效果图、自己创作的视觉作品，图片本身能新增信息。先确定每张图片要证明的事；没有有用/有权利的图片不硬加。
3. thread 串推：多个彼此不同但连续的信息单元，读者分步学方法、评估工具或看完整实验；第一帖可独立成立，每帖都有新信息。2 条起，条数取决于真实材料；不得每帖“更多请见下一条”吊阅读。
4. long_post 单条长帖：一个连贯论证或较复杂的案例，拆成 Thread 会损害逻辑；建议先给主题、判断与阅读收益，用少量小标题和自然段落。Premium 长帖功能是 Post，并非 Articles。
5. article 独立文章：具有明确研究深度、完整证据、可按章节检索的系统性文章；单独核用户可用的 Articles 发表资格。输出标题、引言、正文小标题、证据出处、结论。不要只因字多就转 Article。


## 内容骨架选择（v1.2；先于五种发布形式选择，不替代上文形式路由）

**先调用上游 `ai-copy-production/references/creative-operating-system.md` 的跨题材结构判断（故事/共鸣/新闻/深文/科普/幽默/视觉作品等）**。当且仅当本文属于工具发现/推荐时，再调用 `ai-copy-production/SKILL.md` 的 v2.6.4「X 工具发现/推荐：样本驱动的内容骨架路由」：先判断 R1 结果/演示、R2 单工具流程、R3 可收藏资源合集、R4 新变化/对立认知、R5 技术性能对照之一或合理混合，再根据素材、信息密度、用户明确指定的形式，选择下文 short_text / image_post / thread / long_post / article。**R1–R5 是文案结构，不是平台格式**；不存在“R1 必须视频、R3 必须串推、R5 必须长文”的对应表。已有足够视觉证明可省正文重复，但文本仍须准确说明必要前提和获得途径。

20条研究来源与人工正反回归见 `references/evidence-casebook.md` C3 和上游 `references/quality-contract.md` v2.6.4。高热仅是选题与阅读路径的先验线索，禁止据此预测合格曝光或强迫模仿标题。用户只改一段仍须保真；来源、赞助、版权、AI标记与用户发布权限仍按发布门禁核查。

## 当内容有竞争格式时
- 短观点含一个关键截图 → 可选 short_text 或 image_post；按截图是否证明论点决定，不以“图片更高曝光”定论。
- 多个工具资源 → 只有名称/定位且没有足够新分析，先退回研究；真正有用途分层和原创选型时，正文可短帖或 Thread，不强制清单都成 Thread。
- 一篇深文 → 如果只是若干小技巧，Thread 可能更适用；如果存在需要前后贯通的论证，则用 long_post/article。媒体素材与订阅资格先审查。
- 用户明确指定格式 → 尊重；若不可行，指出具体材料/权限或规则限制，给最小可用替代，不擅自改题。
- 纯阅读与研究型工具推荐无需“本人全部实测”；须明确来源身份和独立判断。

## 中文阅读排版
- 第一屏尽快告诉读者是什么、变化在哪里、为什么和他有关；不强制问句、悬念、反转、数字清单、强感叹号，也不默认“刚刚重磅发布”。
- 自然分段，一个自然段/一个 Thread 条目应有具体信息；删除重述第一条、统一金句结尾、无依据煽动焦虑、过量 emoji/话题标签与无意义“建议收藏”。
- 重要限制与前提紧邻结论，不能藏到第十帖或超长图末尾。
- 每条 Thread 都应可单独阅读、明白与前后关系；编号仅导航，不为拉长帖强制编号。
- 对长帖/文章，优先可靠标题/摘要/小标题和按问题组织的结构，避免复制论文摘要腔。
- 图片使用可证内容：对比要真实且标注条件；引用别人的作品要链接/许可；AI 概念图必须区分示意/真实工具输出。
- ALT 文字及图片可访问性按媒体实际内容编写，不造不存在的东西。
- “50%可见”是 X 奖励规则，不是指定段落行数或图片比例的官方公式。首屏/预览优化仅为可读性编辑假设，禁止称平台验证或曝光保证。

## 技术边界与发布者最终校验
- 非 Premium 常规 Post 的 280 字符限制及 Premium 长帖更高字符上限以用户当前编辑器和官网为准；中文字符、emoji、链接、提及和附件的计算不应采用简单 Unicode len 作为最终字数证据。
- 条件允许可用官方计数库；否则做粗估，只标潜在超限并强制在 X 原生编辑器核对，不说“已精确通过”。
- 无法确认 Articles 权限时生成稿件可行，但标“发布权限待核”。
- 不要未经许可替用户压缩水分之外的独到技术内容；编辑减法不等于删知识和实例。

## 用户可见格式简约契约
- 默认：推荐形式（一句话理由）+ 完整可复制主稿 + 稿件价值与事实边界（不与正文混排）+ 待核发布事项。
- 仅审稿：标明问题/严重程度与最小修法，不自动交替代全文。
- 小改：用户保护的其他段落原样保留，不重写发布状态。
- 作品尚未发布不能填入运营台账已发布；完成制图也不等于审核通过。
