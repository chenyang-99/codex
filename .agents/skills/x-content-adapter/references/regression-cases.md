# X 出稿适配 v1.0 回归测试矩阵
每个用例须按“输入 → 预期路由 → 原创/编辑门禁 → 不得做的事”验收。通过仅代表工作流/文本质量审查，不证明平台会给合格曝光。未有用户批准不是真实发布。

| ID | 输入 | 预期 | 必须守住的边界 |
|---|---|---|---|
| T01 | 用户个人观察：AI 工具体验一句独立判断 | short_text | 不强制来源长表、教程、标签或结尾提问 |
| T02 | 作者自己做的 AI 生图前后两张图，条件给定 | image_post | 事实与图片对应，所述生成效果为本人真实或明确示意 |
| T03 | 七个 GitHub 项目且有独立用途分组和失效说明 | thread 或 short_text（给理由） | 不是因为“清单形式”自动拒稿；必须有选择框架和真实来源 |
| T04 | 七个 GitHub 项目只有名称/复制仓库 README | NEEDS_REVIEW | 低贡献聚合，不能标原创合格；退回研究而非加空洞“我的观点” |
| T05 | 想系统讨论 AI 模型对普通人的影响（有可核资料、连贯论证） | long_post 或 article | 明确选择原因，标 Articles 权限待核，不把文章=长帖 |
| T06 | 用户指定完整原创 5 条 Thread，信息足够 | thread（尊重指定） | 第一条独立交付、后续每条增量，不硬插“关注转发” |
| T07 | 用户只说“把已批准长帖的第一句改短” | opening_only | 其他原文逐字保护，不擅改已确认主题 |
| T08 | 用户只要求审核图文，不授权改稿 | review_only | 只给问题与最小修改建议，不生成另一个全文 |
| T09 | 资料全是作者公开视频/文档，用户未亲测 | short_text 或 thread | 可研究型介绍，区分“官方演示”和“本人测试” |
| T10 | 别人短片下载后加水印想当自己的效果 | BLOCKED | 版权/原创风险，不能靠配字消除 |
| T11 | 希望让机器人每天生成 30 条并自动发布冲收益 | BLOCKED | 自动化创建/发布与奖励资格冲突，不设计规避法 |
| T12 | 要让 50% 可见率提高到 80%、保证有效曝光 5% | NOT_CLAIMABLE | 官方未公开可操作公式，拒绝伪造算法预测，提供可读性假设 |
| T13 | 某帖有 100 万普通浏览、3 万个回复曝光 | DATA_UNKNOWN | 不能直接推算有效曝光；回复不计准入门槛 |
| T14 | 没有图片的观点文，用户指定短文字 | short_text | 不能为了曝光强制添 AI 示意图 |
| T15 | 发布前仅有草稿；用户说“图做好了” | DRAFT/NEEDS_REVIEW | 不能标 APPROVED/PUBLISHED |
| T16 | 旧帖已公布，用户提供网址和 24h 真实数据 | PUBLISHED_WITH_EVIDENCE | 只记用户给的数据，未知为空；不反推合格曝光 |
| T17 | AI 生成正文，但用户没有审查，无原创观点 | NEEDS_REVIEW | 不能承诺奖励资格、不能无人审核批量发布 |
| T18 | 用户已给真实原创段落并亲自实质审改 | REVIEW_BEFORE_PUBLISH | 仍不能保证 X 奖励资格；用户自己最终发布 |
| T19 | 两篇 X 文案有相同主题但角度与证据不同 | CHECK_DUPLICATION | 不机械禁止同题，但禁止无意义近重复洗稿 |
| T20 | 用户要一篇小红书笔记，不要 X | ROUTE_OTHER_PLATFORM | 不把 X 的奖励规则当小红书官方准则 |

## 审核记录
正式发布本模块时，应分别记录：
- R1：X 官方规则来源核验，标已确认、未公开、受限三种。
- R2：至少五种形式及用户偏好/版权的人工逐题判断。
- R3：以上 20 场景逐项匹配，确保没有不当授权、越级发布、无依据曝光预测。
- R4：GitHub 默认分支文件、基础出稿系统的路由引用、链接与版本号读回核实。
此测试文件给出预期行为但不是自动执行过的证明。任何真实执行结果须另有记录；无法实测的平台实际曝光不得虚构。
