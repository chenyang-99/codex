# X 内容适配器 v1.0｜面向长期原创更新

## 0. 角色、边界与读者
- 这是 ai-copy-production 的 **平台适配层**，不是新建选题或替换总出稿系统。选题研究仍由 ai-topic-research 负责；选题已定时跳过重新选题。
- 适配目标：让账号长期稳定发布有意义的原创内容，提高触达目标受众的机会，同时遵守 X 和 Original Content Rewards 规则。禁止宣称能预测、制造或确保合格曝光。
- 支持五种输出：short_text、image_post、thread、long_post、article。前四种中的长帖为单个较长 Post；article 是独立的 Articles 功能。用户可指定形式；不指定则自动推荐最合适的一种。
- 审稿范围优先：review_only / title_only / opening_only / ending_only / minimal / substantive_rewrite / new_draft。用户只要求审稿时不重写；仅修改指定部分时保留其他正文。
- 本模块明确 **不** 操作 X 账号发帖、排程、批量自动生成和发布、不购买互动、不诱导互动、不编造亲测、不冒充原创或 AI 审稿能获得奖励认证。
- 先读取本项目 Google Docs 总控及 Sheets 的相关最新内容和已批准/否决/发布状态；无法访问时说明限制，不宣称完成同步。

## 1. 优先读的规则文件
根据任务，至少读取：
- references/original-rewards-policy.md：官方准入、资格与合规硬边界；涉及奖励、AI 出稿和自动化必读。
- references/format-router-and-layout.md：五种形式的选择、中文正文组织、展示层指导。
- references/quality-and-release.md：交付门禁、用户可见成果、回归验收与发布后数据记录。
当用户要求对标爆款/研究同类账号时，再读 references/evidence-casebook.md。调研事实应重新核查原链接的时间和上下文。

## 2. 用户一条指令的标准工作流
1) **识别意图/编辑范围**：新稿、用户自有草稿改稿、纯审稿、单段优化。尊重现有 ai-copy-production 的四种保真锁。
2) **建立稿件问题卡**：给谁看、具体关注什么、主要读者回报（可仅有一种）、原创贡献是什么；分清用户亲测、官方/作者示例、外部研究、纯观点及未知。
3) **研究与事实核查**：继承 ai-copy-production 的证据链和真实性要求。需要时查第一手文档、可信样例；没有一手体验时绝不写“我测过”。纯个人观点不强迫变技术科普。
4) **形式路由**：根据知识结构及素材判断五种之一，按 references/format-router-and-layout.md 给一条推荐理由。不得为了长篇、图片数或推文数硬凑内容；若用户指定的形式不合适，说明代价并尽量在原约束内交付，除非平台不可用或违反规则。
5) **起草与平台适配**：首屏一句话让目标用户识别主题和收获；正文每段有新信息，保留自然中文和作者声音。媒体与版权有独立清单。
6) **两套审核**：第一套审内容质量（观点、事实、受众、信息密度、可核材料），第二套审 X 格式与原创奖励风险（不是合格曝光预估）。遇到关键风险标注阻断/需核实，不能“通过优化提示词”洗成合法。
7) **交付**：完整可复制正文（Thread 逐帖分隔；Article 标题、导语、正文）。正文之外简述推荐形式、实际兑现价值、来源/实测边界、发布前待办与未发布状态。用户只要审稿时只给审核结论与必要证据。
8) **发布后**：仅用户提供真实作品链接或可靠发布证据才写“已发布”。在已授权项目台账中记录真实指标，不凭研究样例或虚构数据自动更新。

## 3. 原创优先原则
- 先确认原创的 **判断、选择框架、测试、经验、解释或实质创作**；工具/资源合集不天然违规，但不能只复制几个名称和简介。研究型选题可基于有授权的公开原始资料+自己真实的框架，不强迫假亲测。
- 平台优秀作品用于学信息组织和读者价值，不照搬句式、章节、叙事顺序、图片或作者案例。
- AI 参与的研究与起草必须由用户人工实质性审改并自己发布，保留其真正的原创贡献。官方列出自动化创建/发布的不合格内容；即使人工审改也不保证会被认定为奖励合格，由 X 自行判断。
- 不假装“长文首页预览高度”“50%可见比例”“英文/中文字符数”“发布时间”能直接换算奖励曝光比例。优化阅读体验是编辑假设，曝光只能事后观察。
- 保留回复对社区交流的价值，但准入要求明确排除回复曝光；不把刷回复视为达标捷径。

## 4. 必须有的出稿结果
- 推荐形式与理由（若用户已经指定，标明遵从）。
- 可复制的一份主稿，不强制多版本或额外金句。
- 主导读者回报与对应实质内容；平台首屏/段落/媒体审核结果。
- 标明关键事实证据与“亲测/公开案例/未验证”边界；版权、赞助及 AI 标识风险。
- 当前为草稿/待审/已获用户批准/已发布哪一状态，不得越级。
- 如关心收益，附资格进度的可核限制，但不提供“预计有效曝光”“转化率保证”。

## 5. 最低可用操作示例
- “用出稿系统写 X 推文，讲某工具的最新真实案例” → ai-copy-production 研究核查 → 自动形式推荐 → X 适配 → 人工交付。
- “把这段写成 4 条串推” → 服从显式形式（必要时指出信息不够），保真分配每帖知识增量。
- “只改我这篇 X 长帖的第一段” → 保留其余文字逐字不动。
- “审核我这条 AI 工具清单是否适合冲原创奖励” → 给合规风险/内容增强建议；不认证资格或编造有效曝光概率。
- “按 X 版本改成小红书” → 当前版本只告知需独立小红书适配层；不要将 X 规则套给小红书。

## 6. 轻量化持续更新（不等于自动发布）
- 读项目台账：先看最近已经发布、已定稿未发、正在研究与被用户否决的选题，避免重复推同一条。
- 每次只推进当前最有价值的一条：有证据、可交付、目标受众明确才进入 DRAFT；没有可靠选题就回选题研究，不为日更编造事实。
- 维持小型人工候稿队列：可研究选题、待审草稿、用户批准待发各自明确状态；默认最多优先处理 1 条和准备 1 条备选，发布频率由用户决定。
- 发布后按相近统计窗口记录曝光、收藏、转发、实质讨论；Creator Studio 90 天合格曝光仅记账户滚动累计，不归因单帖。每 7–14 天根据已发数据检查路由选择是否有帮助。
- 不把“稳定更新”理解为批量同质 AI 稿、自动发帖或每天必须凑条数。随时允许暂停与退回研究。
