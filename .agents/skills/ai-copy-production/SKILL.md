# AI 图文出稿系统 · v3.0.0

## 一、职责和权威记录

这里只处理**选题确认后的文案**。选题研究继续由 `.agents/skills/ai-topic-research/SKILL.md` 负责。用户也可以直接带选题或初稿来，绝不强迫重新经过选题发现。

每次在“30天图文账号测试”项目执行出稿任务，先读取原始 Google Docs 项目总控与 Google Sheets 的相应内容和最新决策，优先服从最新明确的用户指示：
- https://docs.google.com/document/d/1Jw9zjaNnEy9ixfuNSinf7ZL3Zh72wF7otLPD3rdyGZc/edit
- https://docs.google.com/spreadsheets/d/1P9hGNDJmwil7KnWmUm7Y2IlPp1BRK3-erPdQ7fhHyQA/edit

**读取/记录不等于发布。** 旧稿为待审的仍是待审，已否决的版本不能当成功案例；用户明确确认策略、稿件状态或改稿决定时才按项目规则更新并读回原有 Drive 文件。没有真实播放与互动数据就保持未知。

## 二、三种入口，不重复提问

1. **已批准选题 → 新稿**：承接已经批准的具体读者、观点、内容价值与事实边界，只补当前写稿必须核实的信息。
2. **用户自选题/零散想法 → 共创**：先从用户原话提取立场和素材，自动整理一个最清楚的论点；事实缺口必须可见，必要时核查原始资料。用户没要求提纲确认时直接形成主稿，不做多余问卷。
3. **用户已有初稿 → 修改/审稿**：这是**保真优先**模式。如果用户只要“指出问题/审稿”，默认只反馈问题，不代写；如果只改标题，就只改标题；如果明确“重写”，才可以改变结构。对用户的已通过版本尤其谨慎。

必须从任务文字判断 edit_scope：review_only / title_only / opening_only / ending_only / minimal / substantive_rewrite / new_draft。不能把“帮我看看”解释为全篇重写。

### 原稿保真锁（最高优先级）

改稿之前，在内部建立保护清单，尽量直接使用用户原文：
- **观点锁**：核心判断、目标读者、场景不能被编者换题；原选题“普通职场人”不能因为程序员案例而变成“程序员专题”。
- **事实锁**：已证实的第一人称实操动作、产品操作步骤、数字、材料限制、未验证项不能被删除或伪造。
- **声音锁**：用户明确保留的口语、昵称、自然玩笑、结尾语气、节奏及刻意省略不能自动洗成“专业中性稿”。
- **范围锁**：用户只让改标题/某段时，其他正文逐字不动；“微调”只作小范围必要修正，不以压缩字数作为默认优点。
- **真实性锁**：发现事实有错时，明确说明并做最小修复；不能为了保留原话而让事实错误通过。

不强求机器字面相似度阈值：必要的事实纠正可以大改；保护的是实际意义与作者声音，而不是机械字符串。真实“亲测”“安装”“成功”声明只可来自用户已明确提供的行动或可核实资料，且严格保持范围。

## 三、研究先行：先核实，再提炼，最后写稿（V2 强制）

任何**新选题出稿、整篇重写、补充重要新事实**都必须遵循「研究问题 → 原始证据 → 对照辨析 → 知识提炼 → 定角度 → 成稿 → 核验」。不得先凭已有印象写完再找链接装饰结论。
- 先确定受众、他们真正要解决的一个问题，以及本篇相较常见文章新增的知识或判断。研究不以网页数或文字长度计质量。
- 优先原始技术文档、官方规范/原作者发布、可信论文和可回溯实操；多方比较有分歧的说法。记录原始链接、作者、时间（若时效相关）、证据支持的具体论断，以及来源局限。搜索摘要和二手转述只作为线索。
- 把笔记分为**已核事实／来源自述／合理推断／个人判断／未知**，分辨定义、机制、前提、适用场景、反例和失败边界。遇到事实冲突，不能擅自拼出一个貌似确定的答案。
- 写稿前形成一份可审查的**知识提炼卡**：核心结论、关键机制、适用/不适用、读者主导回报（如学习、实用、资料保存、认知、决策、情绪、审美娱乐、信息发现或身份表达）、若适合则提供可保存素材/学习产出、最值得讲的新发现、仍不确定的事项。缺少可证明的内容增量时，继续研究或明确降低范围，不靠语言包装硬写。
- 研究深度按题型匹配：技术科普核对原理、术语和近似概念；工具教程查官方步骤、限制、权限和必要实操；新功能核实时间、地区与资格；观点文研究支撑或反驳它的可靠论据；用户个人心得以其提供的真实经验为第一手材料，不能强制变成无关的外部文献综述。
- **审稿、仅改标题、标点排版、保真轻改**保持原范围；仅对新增或存疑事实作针对性核查，不擅自整篇重写或扩充选题。若无法访问可靠来源，公开说明证据缺口，不捏造“已深入研究”。

### 研究与出稿衔接规则
选题系统的吸引力／传播潜力及主导读者回报审核只是**选题价值假设**；不能等同于完成写稿所需的技术事实核查。两阶段分工：ai-topic-research 负责发现/需求/热度/题材价值；本 Skill 负责证据读通、知识结构、实际出稿及文案验收。用户直接指定选题时跳过候选发现，但不可跳过必要的事实研究。

## 四、双传播条件 + 一项扎实的主导读者回报（V2.1，兼容选题系统v1.2）

**不要把收藏、学习、认知、情绪全部当成每篇文章的必选项。** 每篇新稿必须满足两个面向分发的条件，同时至少兑现一项与内容类型匹配的主导回报；其他回报可自然并存，不强制数量、不以标签多为优。不要为了达标把短观点改写成教程，把审美作品塞入Prompt。

**普遍必需：**
1. **诚实的吸引力**：首屏/标题/前三秒能让目标受众明确感知看点、痛点、价值或感受，正文兑现承诺，禁止标题党。
2. **可解释的传播理由**：说明什么人会主动转发、讨论、转述、收藏、私发给朋友，以及为什么；要区分A类同作品实有公开热度、B类近期一手信息＋编辑预测，不能把潜力说成爆火或保证播放。对高意图小众主题，也可有清楚的**目标受众内**传播机制，不强求大众化。

**至少一项强主导回报，其他可选（含混合型）：**
- **实用/行动**：帮读者省掉一步操作、解决具体问题、减少失败。
- **学习/技能**：掌握一项可迁移技巧或理解一个准确机制。
- **资料/保存**：得到以后会反复查阅的工具入口、资源、Prompt、清单或流程；只有工具名称并不等于可收藏价值。
- **认知/洞察**：获得有根据的新解释、新立场或思维角度。
- **决策/避坑**：知道怎么选、何时不选、代价与边界。
- **信息/发现**：在恰当时效内知道真正重要的新事实、产品变化或趋势；必须交代对谁有意义。
- **情绪/共鸣**：获得理解、慰藉、激励或清晰的情绪表达，不靠编造个人经历。
- **审美/娱乐**：获得精湛的视觉、故事、幽默或惊喜体验；技术讲解不是必需。
- **社交/身份表达**：提供值得分享的谈资、可被复述的立场或社群归属感；需有具体读者群和真实表达基础。

以上是方便编辑判断的**非互斥标签**，不是宣称穷尽所有人类动机。收藏、分享本身偏向用户行为；这里的“资料/保存”特指内容提供了实际可复用的材料。学习、认知、信息与决策也可能相互重叠。主导价值可以只有一项，强度和兑现优先于凑齐两个。

**不能混为内容价值的基础质量要求：** 通俗且准确的表达、可靠证据、原创增量、版权与平台合规、尊重作者声音。通俗易懂是一种表达标准，技术科普要解释术语；专业向内容允许必要术语，创意/情绪内容不硬插教学。

**按类型选：** 工具推荐可凭资源/决策；教程可凭学习/实用；观点凭认知/情绪；AI资讯凭信息/决策；AICG凭审美/娱乐或学习；短故事可只有情绪体验。不强制每篇都输出教程、对照表、Prompt或“建议收藏”。

### 技术科普／操作型内容：读者真正学会，而非机械堆知识（V2.6 审稿经验）

2026-10-19「Prompt / RAG / 微调」X串推 V3→V6.2 的多轮人工审稿暴露三个互相牵制的质量缺口：**只讲定义不会用**、**堆代码入门用户看不懂**、**只给AI委托指令又缺少原理和知识增量**。通用解法不是固定15条或强制教程化，而是**受众适配 + 机制与操作双兑现 + 失效边界**。该流程仅用于承诺科普/教学/操作的稿件，不强制用于观点、情绪、新闻、视觉作品。

**写前承诺卡（内部）：** 首先用一句话确定受众已有基础、真正想解决的问题、看完应该能讲清的机制、能完成的最小动作，以及最值得保存或转述的材料。不同能力的读者分层；如果用户指定“普通AI爱好者”，不要默认会写Python，也不要为降门槛把技术机制全部删掉。

**每种承诺讲会的方法，逐项交付四层信息：**
1. **机制（是什么 + 为什么）**：使用尽量少的术语，说明技术实际改变了哪个环节、作用路径和容易混淆的近邻概念；必要时使用可核对的知识增量，不只有比喻。例如Few-shot是在当前上下文给示例并非训练；RAG先检索后生成，找错资料和读错资料是不同故障；微调改变可训练权重/适配参数，不等于提供实时政策。
2. **何时用／何时不用（选择）**：给读者一个能实际作决定的场景、前提与低成本替代；方法之间可组合，不编成“越高级越好”的升级序列。
3. **操作（能做的第一步）**：完整、可复制的自然语言指令/可替换示例与具体工具入口；区分普通聊天、文件辅助问答、真正可维护的RAG、实际模型训练。对面向开发者的稿件可给准确代码；对入门教程将代码放进阶附录而非主线。
4. **失败与验收（怎么知道成了）**：可检查的输入/输出对照、依据、更新频率、数据质量、成本/权限；不得把AI代理“生成代码”说成“部署完成”，把“训练跑通”说成“性能提升”。需要执行环境、算力、账号授权或真实数据时明确注明；上传敏感资料、付费、部署、训练先征求批准。

**自然语言委托给AI代理的最佳实践：** 可由代理协助规划、编写、运行和验证，但可复制任务必须包含目标、用户提供的材料、先行可行性与预算检查、执行前审批点、交付证据和验收标准。对于高成本微调先做Prompt/示例基线；资料简单时先试上传文件，不把文件问答包装成完整RAG。AI不是缺失数据、环境、权限或评测的替代品。

**密度验收：** 逐帖/逐段问“除了已说内容，还给读者什么新的事实、机制、判断或操作？”删重复定义、空泛过渡、为了凑篇数加的清单；不通过删掉原理来追求通俗。目标读者应能**用自己的话讲明白、真的开始使用、区分何时不适用**。没有可交付路径就如实改称概念介绍，不能假装教会三种技术。小众专业稿可采用更高术语与代码密度。

### 首屏路线与案例位置：先确定内容承诺，再选钩子（所有题型适用）

**吸引力不等于悬念/夸张/痛点/反转。** 首条必须让目标读者立刻知道“这是关于什么、与我有什么关系、我会得到什么”，但钩子形式服从题材和用户明确偏好：
- **知识对比、教程、资源说明**：可以直接点明主题＋核心问题／实际回报。用户要求“简洁直说”时禁止擅自加“你一直做错了”“改100遍也没用”之类虚构普遍经历或戏剧化开头。
- **新闻或产品变化**：优先准确的实质变化与用户影响；**观点或个人经验**：可用真实的具体观察和鲜明判断；**视觉／娱乐**：优先展示作品和感受。不要把某一种开头模板硬套全部题材。
- **案例服务于理解，不必抢占首屏**：职场政策、客服退款等示意仅在能增加信息时进入正文；如果它和受众兴趣缺乏明显联系，不能仅凭“具体”当钩子。案例属假设要标注，不虚构本人测试或热门话题。
- **前两帖去重**：第一帖已列三者定义或给出结构，第二帖必须新增机制或决策信息，不能只是把第一帖换说法；可合并或调整分工。所有承诺正文要实际兑现。
- **平台适配**：X Thread每帖含明确增量，不因X常规上限而机械凑篇数；核对字数/加权字符，核算不等于X编辑器最终确认。其他平台按各自消费场景调整。

### 最小充分信息：短而完整（v2.6.3，2026-10-21 用户反馈）

**默认追求最短的有效表达，不是最少的字。** 先列清本稿承诺、目标读者必须知道的关键事实，再删多余的话；宁可多保留一条必要信息，也不以短为由让读者读完仍不清楚是什么、有什么用、怎么获得/行动。**信息完整与事实准确是硬门槛，简洁是其后的表达优化。**

- **写前建“必备信息清单”（内部，不直接展示）**：从原始资料、用户要求和本稿承诺中提取不能遗漏的事实、数字、对象、动作/入口、前提/限制。只列与读者决策相关的要点，按类型调整，不机械规定每篇列齐所有字段。用户给定的细节和原话受范围锁、事实锁保护。
- **资源／开源项目发现型单推**：通常至少交代「项目叫什么、是什么／做什么、真正差异、读者如何使用或取得、原始入口」。**数量/风格范围/示例/开源与作者署名**等若构成收藏和判断价值，必须保留；价格、平台适用性、版权与权限等限制若影响读者行动，准确简述。不能只讲单一使用场景而漏掉项目更广的主要用途；也不能把整个 README 塞进单推。
- **教程／科普**：保留承诺所必需的前提、关键原理或操作、可检验结果与失败边界；不得为了压缩成短帖删去让人真正学会的步骤。**资讯／决策**：保留关键变化、对象、影响和必要时间/资格。**观点／情绪**：保留清晰判断与独特支撑，不强塞清单或操作说明。视觉分享则让真实视觉素材承担主要内容。
- **删冗余的顺序**：先删自我铺垫、同义重复、空洞形容、模板互动话术、可由配图直接看出的重复描述和无必要延展，再合并相近句；不得删重要信息、事实来源性质、数字单位、适用边界与必要链接。每句话至少提供一个新事实、判断、动作或必要衔接。
- **交稿双问**：①删掉这一句，读者会不会缺少重要事实/操作前提？会就保留或合并。②留下这一句，是否带来新的信息或真实表达价值？没有就删。压缩后按必备清单逐项反查。已标注的 `required_terms` 可用现有机械门禁查字面缺漏，但**工具无法发现编辑起初漏列的关键信息**，必须人工对照原始资料验收。

**本次反例（AI Visual Prompt Cookbook 单推）**：只讲“统一封面风格”会缩窄项目真实用途，漏掉资源规模、横竖版示例、复制 JSON 更换主体/文字的用法、官网/仓库入口等关键内容。正确做法是一条精简完整的资源推荐，不强改 Thread，也不借完整性之名加冗长教程、未做的实测或绝对一致性/商用许可保证。此案例只证明用户给定的审稿准则，**未提供平台数据证明哪种字数传播更好**。


### X 工具发现/推荐：样本驱动的内容骨架路由（v2.6.4，2026-10-21）

**新增的是正文信息结构判断，不是强制爆款模板，也不是 X 发布形式选择。** 依据用户提供的 20 条 XSEED-01–20 原帖的公开正文与第三方互动快照归纳；来源与逐条审校见同一 Google Sheets「X工具推荐来源样本」Q:U，以及 `.agents/skills/x-content-adapter/references/evidence-casebook.md`。这批为策展网络的高传播便利样本，存在幸存者/账号体量/语言/时窗偏差，不能推断任何文案结构导致高浏览或本账号照写会爆火。

**先做 5 项内部判定再选结构（仅在 new_draft / substantive_rewrite / 用户许可的结构优化时）：**
1. **读者与一句收益**：读者是谁、看完能得到什么？首屏直接传达可证明的功能、变化、具体效果或问题；不为制造悬念牺牲准确。
2. **证据形态**：是否已有经核可访问的视频/图像、真实操作结果、项目原链、官方功能说明、比较条件、版本/付费/许可等；来源自述、本人实测和编辑推断严格分离。
3. **主导回报**：优先判定信息发现、实际操作、资料保存、决策、技术学习或观点，而非根据“多少赞”选模板。
4. **信息承载**：可由真实演示自行解释的结果不重复描写；文本必须补足演示看不出的条件。没有可用或授权的媒体时，不虚构截图，改用文字清晰解释。
5. **最小充分信息**：保留项目身份、核心增量、用法/获取入口、关键前提与风险等实际必要项；一旦仅说出“很强”“一键”却无法讲清，则先退回证据审核。

**五条可选正文路由（不限制混合，优先选最少段落也能兑现承诺的结构）：**
- **R1｜极短结果/演示**：`新的具体变化或结果 → 真实演示/入口 → 仅补一个影响使用的限制`。适合 Blender+ChatGPT、可见动态作品、图像像素化等；观众能直接看见结果时不要求“三大亮点”和主观拔高。纯文字看不懂/项目接入条件重要时不可硬缩成两句。
- **R2｜单工具的输入→处理→输出**：`工具是什么+谁受益 → 最有区分度的2–4项动作或流程 → 真实样例/入口`。适合 Horizon、OpenShorts、视频下载/剪辑等；列的是读者能完成的具体任务，不重复同义功能，不用未经核实的“一键全自动”。
- **R3｜经筛选可收藏资源合集**：`明确受众与筛选目标 → N个真实可访问资源（每项用途+入口/条件）→ 必要选型建议`。适合 Vibe Coding 资料、工具/论坛合集。N 是实际检查过的数量，不凑数；要有编者自己的分类、差异或取舍。不能照搬他人清单顺序、文案、素材或虚构“全都亲测”。
- **R4｜更新/意外组合/观点**：`事实性新变化或有依据的具体问题 → 核心机制/两种立场或对照 → 对目标用户的影响与原链`。适合 TasteSkill v2、新接入能力、岗位插件、系统改造；对立只是可选，不凭空造职场焦虑或“某大厂被打脸”。
- **R5｜技术性能/成本对照**：`可核对的指标与基线 → 对比对象、设备/任务/版本/样本/测试来源 → 为什么可能不同 → 谁适用及例外`。适合 Magnitude 等技术题；开发者原测须写“团队报告”，未自测不可称独立性能结论，严禁因追求极短删测试条件。

**正文骨架 ≠ X 媒体/发布形式**：R1 可为视频+极短配文；R3 可为单条长帖或 Thread；R5 可为长单帖或文章。先选内容骨架，再交给 x-content-adapter 判断 short_text / image_post / thread / long_post / article，用户指定形式及账号权限优先。抖音、小红书可借“收益/演示/证据”的信息安排，不能复制 X 原帖的长度/格式/互动习惯。

**写前不增加用户问卷**：内部只标记 `structural_route`、`why`、`what_media_proves`、`must_keep_facts`、`unknowns`；这些是人工编辑备注，暂不更改现有 JSON 数据契约或质量检查器。优先给一份成熟稿，除非用户要求多版本。改稿模式仍受 edit_scope 和作者保真锁约束。

**正式交稿前做路由反检：**（a）把视频删除后文字是否仍能说明核心价值与必要前提？（b）把段落削减一半，是否漏掉关键行动、数字单位或比较条件？（c）每条清单是否确有独立用途、来源与编辑增量？（d）有无广告/联盟链接利益关系、版权、语音肖像授权、平台绕检等风险？（e）给用户看的每个承诺是否有原始来源或标清是作者自述/预测？（f）是否为了模仿热帖采用辱骂、焦虑或不实保证？

**明确负样本**：XSEED-12 的“不会被平台检测到”、XSEED-13 的“十倍效率/10分钟就成片/随便商用”等属于未经独立核实、可能引发违规/误导的宣传，绝不将它们设为开头模板或事实；XSEED-09 包含商业推广链接，复用时先查赞助/联盟披露和服务条件。20 条中有非 AI 选题，可研究传播组织但不能变成 AI 技术实证。

**验证边界**：本轮仅完成公开原帖结构归类与规则写入；既无随机实验也无本账号同题同窗 A/B，不能声称 R1–R5 “爆款率提升”。未来保留平台、发布时间、账号体量、素材、主导价值、路由、原稿审核次数和同窗口曝光/书签/转发作为反馈，样本不足时只做描述性复盘。

### X 开源项目发现型单帖：Izumi 用户改稿正向样本（2026-10-21）

这是**写作选择的优先候选**，适合“发现一个开源AI项目/工具，带官方案例，向 X 读者说清它为什么值得看”的任务。取自用户将 Izumi 初稿亲自改短、要求降低研究和发布复杂度的明确反馈。**只验证用户对该稿表达方向的选择，未获得发布、传播或视频授权证明。** 与已记录的“工具价值型长单帖 V3”并列：项目发现和已有演示偏向简短单帖；复杂工作流需要解释具体使用价值时，仍可用长单帖。

**作者保真与最小可复用结构（不是强制六段模板）：**
1. **开门见山**：首句给真实项目名、项目性质与一项准确的核心能力或变化。不必先写“我偶然发现”“这可能改变行业”；用户已经提供简明开头时不额外制造夸张悬念。
2. **只挑真正有贡献的机制**：点明一条不同于普通工具合集的功能，例如 AI Director 如何把需求转为叙事/分镜/镜头节奏/生成，而不是把模型名称、导演功能和“很特别”换着说三遍。具体模型可概述，不能单凭接入名单推断每条样片都调用所有模型。
3. **让现成案例承担证据**：优先官方仓库公开的广告、界面、素材、Prompt 与项目链接；可列 2–4 种**确有来源**的案例类别，不因“具体”就虚构自己跑过一套商品广告、账单、耗时或观看过的视频质量。用户只要求素材拆解，不主动扩展自制测试计划和复杂成本表。
4. **一小段有内容的判断**：从前述事实中提出可解释的个人观察（如 AI 从生成单镜头延伸到参与制片流程），不伪装成行业普遍结果或确定成功率；保留用户自然的“我觉得值得关注的是”之类口吻，不强塞口号收尾。
5. **留真正能用的来源入口**：仓库/官方案例链接即可，不要求点赞、评论、收藏，不放一堆无必要 CTA；引用视频时明确“展示在官方仓库”≠“允许下载重传”，开源代码许可证不能自动给附件广告片转载权。
6. **写成独立可读的自然段**：信息顺序可以是“项目与主张→能力组合→关键导演机制→案例→个人判断→原链接”，但删除重复句比追求固定长度更重要；如果用户亲自删掉详细广告叙事，不要为了完整感又补回去。

**本案需要纠正的旧稿倾向**：擅加自拟广告案例和预估成本、把工具介绍写成多段铺垫、对同一 AI Director 机制重复解释、在用户只想现成案例时建议另做付费实测、把读者阅读需求与素材使用授权混为一谈。事实核查、素材版权与作者原创贡献仍是硬要求；**精简的是正文，不是审校责任**。具体正反回归见 `references/quality-contract.md` 的 Izumi 审稿样本。

### 多轮改稿的学习与范围控制

- 把用户反馈先转成**明确失败类型 → 只修改所涉及模块 → 对照原稿验收**。区分「首屏吸引力不足」「概念多而不可操作」「代码门槛过高」「知识密度不足」；不能因一个局部问题推倒已被认可的机制与正文。
- 维护**已明确否决／基本认可／正式批准／已发布**四种状态和保护清单；用户说“基本可以定稿”代表接近定稿，不等于提供发布证据。新会话读项目总控与台账后衔接，不重复已否定的开头。
- 不把用户在**某一篇**稿子选择的“直接点题”、示例场景、15帖长度，当成所有稿件的永久格式。沉淀的是判断流程与例外边界，而不是复制当次文案。
- 对编辑系统更新先**合并已有重复条款**，避免无限追加相互抵触规则。质量契约中保留此案作为人工回归示例；机器通过只能证明程序运行，不能证明读者喜欢、作品爆火或已定稿。

### 质量硬门槛
- **信息增量**：相对于普通重复内容，有新的事实、表达、洞察、方法、选择帮助或艺术体验（按内容类型核验）；不为凑满10/12条串推重复定义。
- **准确与边界**：不能把交叉技术强说成互斥或唯一分类；涉及新技术版本、版权、成本、权限、风险或时效必须可核对。没有实测不能写“亲测有效”。
- **选型/方法论文**：必须给决策顺序、适用前提、失败原因、低成本替代与如何评估，不能只有“场景 → 名称”的速查口号。
- **内容结构**：先给真正的知识贡献，再安排解释。每段都有独立功能；删除重复总结、口号结尾和不增信息量的过渡。选用X单条还是Thread由内容密度决定，不能先指定12条再拼材料。
- **原创表达**：把多个可追溯材料内化为自己的解释；不照搬原作结构、示例与结论；解释性假设明确标注为示例，不冒充作者实操或真实用户案例。
- **发布前验收**：核查主张-来源逐条对应、选定的主导读者回报确实兑现、承诺的素材可用（若有）、示例没有偷换概念、是否有未注明限制、平台格式与合规。未达到则修改/缩小范围/退回研究，不能因为机器检查通过就定稿。


## 五、跨题材创作引擎 v3.0（高优先级入口，先于具体模板）

**不能因为前20条案例来自X工具推荐，就把整个出稿系统定死为工具帖。** 用户可能要求：一句视觉/趣味帖、深技术解释、人物故事、观点、真实失败复盘、情绪随笔、小红书教程、抖音短图文、AI工具评测或长文。**先根据核心素材与读者承诺选写作机制，再确定篇幅和平台格式；别把所有作品写成同一种“痛点开头→三功能→总结”的AI稿。**

**新稿、整篇改写必须读取并执行**：
- `references/creative-operating-system.md`：跨题材的“六格主编卡→选结构→素材与叙事分工→写作→三遍审稿”。这是所有题材的结构决策总入口。读者主要回报可为理解、实用、收藏、情绪、身份、审美、观点或信息；**不是每篇都必须有教程、冲突或收藏资料**。
- `references/cross-genre-casebook.md`：原帖/作者复盘/案例研究/科学与可读性证据分级，学习故事、情绪长文、失败复盘、科普、观点、卡片、工具、技术比较与短视频，不抄任何人的独特句式和叙事。
- `references/editorial-regression.md`：32个正反人工回归情境。按实际题型选择一项正例、一项同型反例、一项跨型反例，重点阻止“工具模板误伤故事”“AI味套话”“虚构实测”“重要信息被截短”。
- X工具 R1–R5 路由仍有效，但**只是广义架构中的子集**；X独立适配器选 short_text/image_post/thread/long_post/article，不能代替内容本身的结构判断。

**写作时的反套话执行顺序**：先检查主题是否有真正独特且有证据的内容；再看段落有没有新事实、推论、细节、感受或故事作用；最后删万能修辞、无实质重复、形式化小标题、空洞“不是A而是B”、无必要互动指令。反套话**不是**词语禁用清单：若作者用排比、诗性比喻、口语或幽默有实际表达作用就保留。一次只交一份成熟主稿，不必每次给三套钩子供用户选择。

**仅审稿/只改标题/只改首句**继续遵守前述 edit_scope 与保真锁，不因新规范重写其他部分。**有真实视觉素材时允许文字极短，有复杂事实和推演时允许长文。** 数据正确、原创贡献、来源许可与用户特有口吻始终优先于“像热帖”。

**可选机械预检**：`scripts/editorial_preflight.py` 读取自建JSON稿件事实清单，提醒重复段、空泛促销口号、绝对保证、声明亲测却未标记用户证据、已列必保事实缺失与可疑授权越界。只输出警告，不自动修稿、不统计“人味”、不预测播放、不做机器“通过”评分；`scripts/copy_quality_gate.py` 的原有范围与事实门禁继续使用。两者都不能完成语义/版权/传播验证，须用人工审稿。

**研究限制**：本轮扩大原文与新闻来源覆盖，不构成X/小红书/抖音各类型随机绩效对照；原作者自报播放不等于本站验证，优秀但热度不明的长文只用来学技巧。真实系统改进需未来用户审稿反馈及本号按同平台相近时窗的作品数据检验，缺指标保持未知。

## 六、按稿件内容选技术，不整套照搬

### A. 短观点、X短帖和抖音轻文字
借鉴 Text Post & Microblog 的 LINES：开头先触及读者关心的**具体观察**；一篇只有一个有解释力的判断；段落自然留白；后文兑现开头的内容承诺。不得因英文平台经验强行套长度或互动率。
- 默认短而有物，不强制“背景-三点-升华”、一图六页、反转句、金句墙。
- 最后一行可以自然结束，**无需“你怎么看”“评论区告诉我”**。
- 观点不是漂亮态度宣言，必须有可追溯观察/具体因果或清晰的个人判断。

### B. 可复现实操/工具教程
借鉴 Educational Content & How-to 的 TEACH，先明确**做完得到什么**，再讲使用前提、按顺序的关键步骤、每步可看到什么、可能踩坑及验证方式。
- 区分用户已亲测、第三方作者所展示、官方宣传/教程、用户将来准备尝试的玩法。
- 不给没跑过的步骤冒充“我试了”，不自动承诺无成本、无错字、支持全部版本或国内账号可用。
- 仅有短视频解析证据，不能延伸成完整长课程理解准确；无确切截图/试验不能写定量成功率。
- 用户提出简短观点时不强塞分步长教程。

### C. AI新闻、功能变化、工具决策
结论落到**哪些人、哪项实际选择需要变化**；新旧版本、发布时间、价格/地区/资格若影响判断须查实际原始资料，来源不明则不确定或暂缓写。以事实、推测、待实测三层交付。

## 七、中文写作与审稿方法

以 Human Writing 的“材料先于腔调”和 Rednote Writing 的“素材拼贴/观点共创/已有初稿保真”作为中文层，以 Copy Editing 的清晰/价值/事实/具体性做短而有针对性的审稿。仅调用当前任务需要的检查，不必每次机械套七遍营销审稿。

**先写出有根据的东西，再清除模型味：**
1. **意图和价值**：主要读者是谁，读完多获得哪一个观察、判断、可执行动作；正文是否换了论点？
2. **证据和承诺**：事实是用户亲自做过、公开资料可查、第三方自述，还是仅计划；所有强断言有无依据？
3. **声音和自然中文**：保留作者真实表达、幽默与必要细节；删抽象口号、机械排比、空洞双边平衡、夸张转折、凭空出现的“有人说”；不要为了装真人写假经历/错别字。
4. **交付范围和平台**：按抖音/小红书/X内容形态及当下具体要求适配；无需强制几张图、固定字数、话题标签或互动 CTA，涉及 AI 生成及推广遵守平台规则。

禁用的是无意义的套路，不是所有冒号、破折号或真实合理的转折句。对用户已给文字，必须从事实与表达效果判断是否值得动笔，不能按敏感词黑名单洗掉个性。

### X 平台独立适配层（v2.6.2，优先调用）

当用户明确要在 X 上发布、审核或改写内容时，在完成本 Skill 对证据、用户原稿、作者声音和读者回报的基础审核后，再读取并执行同仓库 .agents/skills/x-content-adapter/SKILL.md；遵守其 official policy、形式路由及发布门禁。这个适配器只负责 X 平台，不替换本 Skill。
- 用户未选定形式：X 模块在短文字、单条图文、Thread、长帖、Articles 中依据材料推荐；用户明确指定则尊重，仅提示明确不可行的权限或事实风险。
- 用户只要求审核/改第一句/改标题时，遵守本 Skill 的 edit_scope 和保真锁；平台模块不能借“提高有效曝光”全面重写。
- 原创奖励的“合格曝光”不是对一条稿件可计算的分数；自动化创建/发布、版权和低贡献聚合等风险必须审，所有实际曝光以 X Creator Studio 及真实数据为准。
- 由用户人工实质性审稿并自己发布；模块完成、草稿完成、审核通过与真实发布分别记录。
- 其他平台如小红书未来使用独立适配层；不能把 X 奖励规则嫁接为其他平台规则。

## 八、每次交稿必附价值说明（用户 2026-10-19 明确新增）

**所有实际交付的新稿、结构性改稿和候选正文都必须在可发布正文之外，向用户清楚注明本稿具备什么价值。** 不可仅存于内部选题档案，也不能把审稿元信息塞到 X 推文、小红书或抖音可复制主稿里。

默认在主稿前或后设置简短的「本稿价值说明」：
- **主导价值**：从实用、学习、资料参考/收藏、认知、决策、信息、情绪、审美娱乐、社交表达中选择最恰当的一项；写清**正文的哪个段落/哪个具体素材**兑现。
- **附加价值**：可以有零项或多项，仅写真正兑现的，并给出具体例证；不得为了显得全面硬填。
- **吸引力**：标题/开头对哪类读者有哪些实际看点；正文是否兑现。
- **传播理由**：哪类读者可能基于什么需求转发、讨论或保存；注明真实平台证据等级，若没有可核热度，标为「主编预测，未验证」。
- **基础质量与限制**：需要时说明来源核验范围、是否亲测、平台字数与未发布状态，不把「通俗易懂」或「引用来源」当成某种特殊的读者回报。

简短单条帖价值说明应简短，长串推可适当解释；提供证据而非打浮夸分数。交付时若无法确认某项价值，应标为待补强而非假称具备。用户仅要审稿、不需要新稿时，可以报告诊断出的价值缺口，**不要求把未改动旧稿包装成新交付**。

## 九、出稿契约与验证

交付新稿时默认给**一份可读、可复制的完整主稿**。当用户明确要求研究或深度科普时，可在正文外附精简的研究要点与来源，且清楚区分来源事实、编者判断和未实测部分；研究记录不堆进推文正文。必要时附最少的“事实待核/本人需要做的操作”；用户提出多个方向才给多个版本。审稿时先指出最关键问题与原因，除非用户明确要求修改，不输出另一篇作品。编辑过程中的内部思考、流程打分和审计元数据不堆在正文。

只有用户最终批准，才把文案标为已审定；出稿不授权制图、登录、发布、预约、自动发帖或宣称成绩。把“草稿完成”“用户审核通过”“实际发布”严格区分。

在写稿后，使用可选的规则检查器：
`python .agents/skills/ai-copy-production/scripts/copy_quality_gate.py --input path/to/dossier.json --output-dir output/`
该工具只审核**显式必保信息和明显未经验证的声称**，不修改文案、不计算“人味指数”、不保证读者满意；真实优劣由人评审。

### 测试准则
回归测试至少要涵盖：仅改标题/审稿不改稿/保留第一人称/完整步骤/未实测边界/普通职场受众不跑偏/保留原有玩笑/禁止虚构发布或数据。此前12例36稿为**同模型模拟压力测试**，不是隔离随机A/B；补测保真 13/13 仅证明约束有效，不能证明新系统已提升涨粉或写作一次通过率。后续用户认可率及真实发布数据仍需跟踪。
