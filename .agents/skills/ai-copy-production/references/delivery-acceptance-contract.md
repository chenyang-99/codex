# 正式交付验收合同｜v3.1（2026-10-21）

> **用户验收目标：给我一份直接就能用的稿子，不达标不允许交付。** 这是出稿终点的不可跳过交付门，不是“写好看就算完成”、不是一个永远能骗过的 AI 自评分数，更不代表用户已审定或实际发布。

## 0. 稿件状态及不可混淆的四件事

- `working_draft`：内部候选稿，不能以成品交付用户。可继续研究、重写、删冗余、拆长帖、补实际入口。
- `blocked`：事实证据、版权、受众主承诺、原稿保真、平台规格、可复制性存在任一硬阻断。**禁止作为“可发布主稿”交付、禁止写入运营台账的“已成稿可发”；只能报告阻断/最少缺口，或先自行修复后再验。**
- `delivery_ready`：所有 P0 硬门槛经编辑逐项核对有正文锚点和证据；平台适配无已知障碍；交付**一份**可单独复制的主稿，链接、分帖、标题、素材/披露按实际要求备齐。这里“可直接用”指**无需再让用户替我们写作或纠错**，不表示自动发帖或 X 平台已接受提交。
- `user_approved` / `published`：用户实际审定 / 实际平台发出，有独立证据。即使 `delivery_ready` 也不能自动提升到这两级。

审稿请求 `review_only` 是诊断交付，不是交付可发布新稿；用户要求局部修改时只验授权范围、相关事实以及平台整篇残存的明显阻断，不借“放行”侵犯保真锁。

## 1. 十项 P0 放行条件（任一失败即 blocked）

| 代码 | 必须做到 | 阻断示例 |
|---|---|---|
| `audience_promise` | 清楚目标读者和首屏具体承诺，正文真正兑现；允许作品/幽默/情绪的审美承诺 | 对所有AI工具通用的“颠覆未来”，不说项目是啥 |
| `primary_payoff` | 至少一个真实且具体的读者回报；能从正文指到实际句子、资料或媒体 | 只有“值得收藏”，没有可用信息 |
| `original_angle` | 本号有独立解释、判断、选择标准、实物/实践或诚实经验，不是复制原简介；纯报告忠实区分原作者主张 | 只是翻译README/把项目功能换词 |
| `specificity_and_completeness` | 必要身份、准确机制、关键用途、步骤/入口/适用限制完整；每段有新作用、非空泛凑字 | 教程不给操作，工具名堆砌，关键前提消失 |
| `truth_and_provenance` | 全部重要可验证事实有实际证据，作者自述/官方案例/独立实测分开；未查到的删或明示未知 | 假称亲测、把官方Gallery称独立A/B |
| `structure_and_pacing` | 写作结构由题材决定，段落有递进、不重复自我介绍、不机械三点铺陈 | 故事被套成“功能1/2/3” |
| `natural_voice` | 清除无作用套话、空总结、泛化促销、重复CTA；保留真正需要的修辞和用户原口吻 | “真正重要的不是A而是B”却没有实际对比 |
| `platform_publishability` | 指定平台/稿件形式可按**已知权限及硬约束**原样发布；字数、分帖、标题、外链和必需素材能落地 | X普通帖超280加权字符，却声称“一条直接发”；把Markdown排版视为X天然支持 |
| `delivery_package` | 唯一完整可复制主稿；没有“此处补案例/自行找图/待验证”占位，必需图片或视频已可合法使用/可由文字替代；必要发布披露已放正文 | 让用户补三张素材，或把写作说明混进发布正文 |
| `rights_and_authorization` | 版权/肖像/敏感信息、第三方图视频、商业推广/联盟关系、AI标识规则、改稿权限均已核对；只在涉及的项目要求实际媒体证据 | 以开源代码Apache/MIT许可证自动推定官方效果图可转载 |

**不是每一条都必须有技术来源、图片、教程、CTA、冲突或第二种读者收益。** 每个门槛都用题材适配的证据证明：诗/幽默可凭精确表达满足价值，而不是强迫资源列表；用户自己的观点可由用户真实经验支持，但不能造实测。

P0 可用新 `scripts/delivery_release_gate.py` 接收一份**编辑自行查证的验收表**和发布主稿做机械放行检查。程序只能保证申报齐备、文本占位和加权长度的保守检查；它**不能**确认每一项独特洞见和可信证据是真实的，也不能把 `pass` 字段本身变成独立人审。未经真实内容核对，绝对不允许为了让命令返回 `eligible_for_delivery` 而自动填全 `pass`。

## 2. 平台发布就绪规则

**X**：
- 用户要“单条推文”且账号长文资格未知时，默认按**普通帖**设计：整条不超过280加权字符，包含链接的 t.co 权重与非ASCII汉字/符号按保守规则检测，**非仅按 Unicode 字数**。不确定边界时留足余量，以X编辑器显示为最终依据。
- 单条内容确实无法保持核心信息时：若用户未限定单条，可明确改为Thread，逐条编号和核对每一帖上限；若用户明确只要一条且无长期帖资格，则**压缩内容而不是给500字伪称“单条可直接用”**；若内容压缩会丢关键事实则阻断并说明权限冲突，不私自假设付费资格。
- `long_post` 和 `article` 只有已确认账号资格/权限时才放行；已明确用户可用则按对应形式交付。若文本配图，配图必须实际可用且权利明确；图片仅为增强时允许干净的纯文字版直接发。
- 投稿文案不放 Markdown 链接标签或幕后“本稿价值说明”；网址应以纯URL写在正文。X普通帖文本权重保守算法只能辅助，上线仍由X编辑器判定。
- 对 Thread：首帖不以“1/?”占掉价值，完整稿逐帖可复制，单帖不能截断代码块/必须可理解；无任意凑篇数。

**小红书**：主标题、正文/图片每页的真实文字、实际图片/封面与标签是否“必需”分清；用户要求纯文字能直接发布就不给必须由用户找图的“制作提纲”。必要图片缺失或无许可则阻断图片稿，降级为不依赖图片的可行稿需尊重用户明确媒介指令。

**抖音**：图文、视频、口播稿有不同交付包；若用户要求直接上传成片，而本次仅有分镜/文案，不能称“已具备成片发布条件”。口播稿可是完整文本，但标注素材/配音/剪辑尚未完成时不得当成完整视频可发布包。

**其他/多平台**：分别验收，不把一个平台的稿件宣称三平台拿来即发；当前实时权限、字数和平台政策存在动态性，无法确认要明确显示限制而不是猜测。

## 3. 内部执行过程（先修再验，绝不让用户代审初稿）

1. **建立事实卡/内容任务卡**：读取权威项目资料，核实原始项目/故事/用户意图与媒体许可，知道本次目标平台和用户指定的形式。
2. **先形成完整稿**：内容架构由素材和回报决定；为主导收益选最短充分版本，非机器模板。
3. **交付前对抗式自审**：站在目标读者和最严格编辑视角，追问“现在能发吗？”“只有README介绍吗？”“缺少关键机制吗？”“首屏兑现了吗？”“我真的核过核心证据吗？”“去掉某段更好吗？”“为什么读者愿意转发/保存？”“有无无权使用的配图？”逐项给真实正文锚点/外部来源。
4. **优先自行修复**：修改/压缩/删不能证明的主张/重新组织，自动工具辅诊；重复审核直到 P0 无阻断，且不引入新事实错误或侵权。
5. **选择发布包与最后预览**：检查平台实际形式与字数，外链均可用；Thread逐条可粘贴；主稿与价值说明分开；交付时默认只给最终稿＋**两三句验收说明**，不把审稿工具JSON或一堆内部版本塞给用户。
6. **遇无法消除的硬阻断**：**不要伪装交付“可发布成稿”**。列阻断事实和最小可行动的缺项；不打“交付成功”；若可合法降级成纯文字/缩小承诺并保留主收益，则自行完成降级再交付，无需反复问用户。
7. **台账状态纪律**：记录 `working_draft`/`blocked`/`delivery_ready` 的理由与时间；只有实际获用户确认/发帖后才记相应状态。不在 Google Sheet 用“已成稿”暗示一定具备发布权限。

## 4. 反向案例：以 Impeccable V2 验证新门槛

历史 Impeccable V2 正文约640个字符，包含大量中文、英文和两个链接；当 X 长文发帖权限未知时，**它不应以“X单条可直接发布”通过**：普通 X 280 加权字符限制。它可以作为内部素材母稿，先压成可发布普通帖（保留真实机制、入口与必要来源）或在未限制形式时拆成Thread；若用户已有实际长帖权限并确认，可按长帖检查。案例中的“官方酒店效果”须明确属于官方展示、非本号亲测；图片若要外传另核许可。关键是**交付前由编辑自行解决**，不交给用户再发现“太长/太像说明书/没有原始证据”。

## 5. P1优化项与真实验收指标

P1 是可继续优化但不应替代 P0 的项目：开头是否有更好表达、作者语气是否更鲜明、有没有合法且高质量的原生配图、是否需要同平台用户偏好校准。不能用“要更好”导致永远不交付；当主稿已无 P0 问题，直接交付一份成熟的成品。

追踪指标：**首次交付无需大改比例、用户一轮直接采用率、用户要求改稿次数、事实/版权/发布格式返工次数、首屏被用户否决原因**；这些必须根据用户真实审稿和已发布作品记录，不能用模拟评分伪造。按平台/内容类型比较。若测试样本不足，不声称改善“爆款率”。

最终一条准则：**用户不需要再当质量检查员，也不需要帮AI把半成品补完。** 这不是“不允许用户提出偏好修改”；用户仍可修改任何稿，且稿件被内部放行不等于未来平台一定接收。
