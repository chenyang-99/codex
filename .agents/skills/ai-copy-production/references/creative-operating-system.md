# 跨题材出稿编辑引擎｜v3.0（2026-10-21）

> **定位**：这是编辑决策系统，不是爆款句式生成器。输入事实、故事/作品、受众、作者观点与限制，输出最能兑现内容价值的结构和一份自然原创主稿。原始 `SKILL.md` 的保真锁、证据责任、平台门禁优先；本文件绝不能覆盖“仅审稿/仅改一句”的授权范围。

## 0. 先理解：传播是结果，不是语气

出稿要同时服务四个不同问题：
1. **值得停下来看吗？** 首屏具备可识别的具体信息、画面、问题、情境或准确的人类经验。
2. **看下去能得到什么？** 故事、知识、操作、作品体验、论证和决策至少有一种充分兑现；不是全部都要。
3. **能相信/能感受到吗？** 具体细节、真实证据、逻辑递进、独到判断与作者声音；来源不足时说清边界。
4. **读者为什么可能传播？** 真正的用途、替人表达、好奇、娱乐、身份、审美、深入理解或参与讨论。这里只能提出编辑假设；实际流量由发布后数据观察。

学高传播作品应解剖“信息怎样交付”，而不是移植标签、煽情、语气词、数字或结尾指令。作者规模、平台、发布时间、已有受众、营销预算、题材热度、媒体质量会干扰归因。单独从高热作品无法推出因果配方。案例证据见 `cross-genre-casebook.md`。

## 1. 稿前的六格主编卡（内部，不强迫用户填表）

只需能在编辑脑中回答，不在每份成稿展示：
- **谁看**：一个具体目标读者和他当前知道/不知道的事；跨平台各自重定，不把“所有人”当目标。
- **为什么现在写**：真新事实、未被解释的矛盾、有价值的资源、本人发现/体验、能替读者命名的感受或审美作品。没有这些，先补材料/缩小主题，禁止编造热度。
- **这篇独有的东西**：原始数据、可信演示、亲历细节、实际截图/结果、精选标准、清晰模型或作者诚实观察。没有独立贡献的转述要改角度或不写。
- **主要承诺**：读完能知道/会做/能保存/能判断/被理解/看到什么。只选一个最强主导收益，可有自然次要收益，不凑标签。
- **可用证据与未知**：用户已做、官方明确、作者自述、跨源核验、逻辑推断、未验证。许可证、素材、订阅、成本、安全与日期一并标记。
- **传播动机与反例**：什么人会转给谁、为什么；最可能反对或失望的人会指出哪个漏洞。没有具体传播理由，不靠“建议收藏/欢迎讨论”补。

## 2. 先判“写作任务”，再选叙事架构（可混合；无固定段数）

| 内容的真正重心 | 优先架构 | 段落功能（只取需要的） | 什么情况下不要套 |
| --- | --- | --- | --- |
| 新工具/版本发布 | **发现→增量→行动** | 用一句说明是什么和具体变化；说清差异与适用者；给原链和重要前提 | 主要是视觉惊喜时避免 README 式清单 |
| 让人看得见的作品 | **成果→过程线索→条件** | 先展示成品/前后对比；补关键设计/步骤、署名与限制 | 没真实素材不编“实测对比”；文字不逐帧复述 |
| 可学的实操 | **目标→起步条件→动作→验收→避坑** | 交付真实最小闭环；按受众基础分层 | 只请求资讯短帖时不要强写教程 |
| 精选资源/工具合集 | **选集原则→用途分类→单项入口→选择建议** | N条只由有效素材决定，每项给不同的实际用途 | 凑数、全无实证、照搬他人顺序和简介 |
| 性能/价格/质量评测 | **问题→测试设计→结果→解释→决定** | 先说对比对象及口径，再数据/机制/边界；可独立复现才说亲测 | 不可删基线、设备、成本与来源 |
| 产业新闻与政策变化 | **发生什么→为何重要→影响谁→尚不确定** | 对比旧状态与新事实、时间条件；勿强迫煽情 | 原因不明时不写成板上钉钉的趋势 |
| 鲜明观点/反常识 | **有根据的判断→关键证据→强反例→修正判断** | 尽量选能改变读者看法的观察，而非空口反对共识 | 没证据时避免“你一直错了” |
| 技术科普/复杂问题 | **真实困惑→直觉模型→关键机制→边界与应用** | 先搭知识阶梯，例子/类比与准确机制交替；可用分层 | 专家文不因“通俗”而删精确术语 |
| 故事/真实复盘 | **场景→阻碍与选择→代价/转折→得到的洞见** | 人、时、地、行为/细节真实，允许没有完美结局 | 不能生成虚构第一人称或伪情节 |
| 人物/情绪与关系 | **具象行为→未被命名的感受→细节展开→转向或余韵** | 共鸣来自准确观察；可留余味，不必概括“三个道理” | 不要求每篇都“传授方法”和收藏清单 |
| 深度分析/调查 | **核心发现→证据链→异议与不确定→综合判断** | 资料有出处，可让读者复核；复杂逻辑必要时长文 | 几句话能说完的发现不要伪装报告 |
| 轻观点/幽默/梗 | **具体观察/反差→一个精确落点** | 节奏和语境主导；可以只一两句 | 硬加背景、价值总结和强制CTA会毁掉效果 |
| 社区/读者互动 | **真问题→可参与语境→有用回应** | 问题必须真实开放，作者先有贡献 | 不使用“评论扣1、蹭互动”的诱导 |

**R1–R5**（此前20条X工具帖学习）是上述“工具相关”几种架构的子集，保留作为细化路径而非总纲。单条可能采用新闻+评价、故事+洞见、视觉+极短演示等混合。形式在结构之后决定：X文字/图文/Thread/长帖；小红书封面+图组；抖音画面与字幕。用户指定媒体/篇幅优先，条件不允许则说明现实限制。

## 3. 开头不是“钩子公式”，而是兑现关系的入口

至少具备一个**真实**触发点；不是每个开头都要问句、冲突、数字或恐吓。
- **结果先行**：有可看成果时开门见山，让画面证明；例“图片和视频直接转像素风，在浏览器中操作”。
- **准确命名**：捕捉很多人经历过但没说清的处境/感受；一定来自真实观察或用户原话，不用杜撰经历。
- **具体场景**：可靠的第一人称、失败时刻、代价/选择让问题可感。
- **事实冲突**：真实数据、前后变化或已有主张的张力，必须有支撑；不靠“某大厂脸都绿了”。
- **独立判断**：先提出作者要论证的主张，后文说明因果与反例。
- **直接承诺**：用户明确要求“简洁告诉我是什么”时第一屏就写主题/具体收获；不制造虚假神秘感。
- **惊喜画面/纯作品**：视觉先行；说明谁创作、如何观看即可。

对同样素材可以内部试两个开头方向，但**默认只交用户一份成熟主稿**。如果两种都写，只用于比较“哪个更准确兑现承诺”，不是猎奇词的竞争。禁止无论题材都先塞“还在XX？看完颠覆认知”。

## 4. 中段写作：材料驱动，不靠 AI 腔填空

使用**信息递进**而不是固定的“首先/其次/最后”。每段至少完成一项任务：提供新事实、真实细节、关键动作、前文论断的支撑/限制、情感变化、必要转场或作品欣赏。可以重复关键词形成节奏，但不要改写同一观点凑版面。

- **事实帖**：每项关键主张能回到原始来源；来源的宣传与独立评测要分开。必要数字保留单位、基线、时窗。
- **观点帖**：选择最强的1–3个证据，主动考虑可靠反例。没有证据不要靠“全网都在讨论”代替。
- **技术帖**：机制、使用决策和错误边界必须准确；不能只有定义，也不能只有Prompt。
- **故事帖**：尽量呈现有意义的行动与具体变化；允许不圆满，禁止“成长、救赎、坚持”大词无事件。
- **情绪帖**：精确的普通动作与物象比抽象感动更有用；不要制造“我们所有人都……”的假普遍性。
- **作品帖**：文字不抢素材；只写凭视觉看不出的信息及作者真实意图。
- **合集帖**：删重复/同质资源，并给区分场景；禁止把开源代码许可自动推及展示图片与模型权重。

**节奏只服务可读性**：短句、长句、段落、留白和项目清单可组合。深文需要铺陈时允许长句；诗性表达与幽默不能被“简洁”机械删除。

## 5. 结尾不等于号召互动

结尾根据读者承诺决定：方法帖给可行动下一步；评测给边界清楚的选择建议；观点交代立场和余地；故事可在某个真实细节处结束；情绪文可留余韵；视觉帖可以只留作品链接；工具帖到原项目入口自然结束。无必要不加“以上就是”“你怎么看”“收藏备用”“在这个时代……”。

## 6. 三遍人审（不以硬编码词表决定文采）

**A｜证据与完整性**：名称、机制、来源、版本/权限、原创来源、引用、素材许可、赞助披露；核心事实缺失必须补，未知不脑补。已经授权的局部改稿只检查改动区域及关联风险。
**B｜文章的价值与美感**：首屏与承诺一致；每段有独立贡献；故事有真正可感的行为；观点有真实论据；教程有成功验收；纯作品有审美体验。字数依有效信息，不人为要求固定800字/三条。
**C｜反套话审稿**：
1. 圈出删掉也完全不损失新信息、真实表达或节奏的句子，先删这类句子；不是见修辞就删。
2. 查能替换任何AI项目名仍成立的万能判断；把抽象形容换成具体事实/场景/效果。
3. 检查“不是A而是B”“真正重要的是”“更值得关注的是”等连接句是否*真的*表达有根据的对照；没有则重构，不搞词汇黑名单。
4. 禁虚构“我测试”“群友推荐”“业内炸锅”“几分钟完成”“完全免费/可商用”“百分百”。真用户原话可保留并注明证据性质。
5. 删除重复导语、空总结、单纯为了押韵的排比、无意义强CTA；保留人物特有的口语、克制与偶尔玩笑。
6. 验证删除之后是否损坏信息链和故事情绪；如果损坏，恢复必要内容。
7. 由不认识项目的目标读者视角复读：看得出是什么、为什么有关、得到什么、证据在哪、何时不适用吗？体验/文学类无需回答每一项技术问题。

## 7. 低成本工具与验证

先使用已有 `copy_quality_gate.py` 检查编辑范围、保护词及明确申报事实（它不能证明好文）；可选再使用新增 `editorial_preflight.py` 对重复段落、强保证/空泛促销表达等提出**非阻断提醒**。该工具不改稿、不打“爆款分”、不拿关键词判定人味，也不能识别遗漏的未知事实。涉及媒体/平台数据仍需人工读证据。

维护两套样本：①跨题材正反结构样本（`cross-genre-casebook.md`），②用户自己批准/否决/真实发布的历史反馈（Google Docs/Sheets）。外部热帖的成功不可等同本账号的发布实验。逐稿记录用于未来比较的类别、骨架、首屏类型、内容素材与证据、目标受众、人工审稿改动与作品真实结果。用相近平台/窗口进行回顾，样本不足不宣称提升。

## 8. 手动小规模回归（写后即做，无需另问用户）

从 `editorial-regression.md` 挑与本稿相近的**正例与反例**各1个，核对：强传播示例会不会被剪成乏味清单；用户原稿会不会被重写；无证夸张是否得到克制；教程/长文/故事会不会被错用工具宣传结构。出现问题时优先修改本稿，不要再往主 Skill 里不断重复追加同义禁令。

本引擎是**可调整的编辑规范**，不是模型权重训练、因果爆款预测器或自动发布系统。
